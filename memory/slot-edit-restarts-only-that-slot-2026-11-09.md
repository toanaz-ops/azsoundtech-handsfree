# Slot edit restarts only that slot (HW-174.Q3, 2026-11-09)

- `AudioEngine::setSlotConfig` is relaxed atomics: a slot edit never needed a device restart or a ring clear. The old `changeSlotConfig` rode the device-restart hooks (stop 8, reset 8, save) only because it was the one available cycle. Per-slot path: stop THAT controller, apply, `discardTapBacklog(slot)` (this thread is the sole consumer), `setSampleRate`+`setWidth` (they ARE the reset: they clear blocksSinceReset and room memory), start if it ran or the engine runs.
- Draining all 16 rings from the message thread while 7 detectors run would make it a second SPSC consumer -- hence the per-slot overload.
- Saves moved OUT of changeSlotConfig: every batch caller (`checkRestoredDevice`, `validateRestoredSlots`, `onCancel` mismatch branch) needed an explicit save at its end because it silently relied on the hook's save. `settingsWriteCountForTest()` is the enforcement.
- While a lane M run measures, skip `applyModeGating` for the edited slot: detection is off on every slot then and gating would switch it on. Soundcheck aborts only if the edit touches the measured slot or channel (before or after), else it runs on.
- LOW-5: no controller/soundcheck thread path takes a JUCE device or callback lock (NotchController holds no AudioEngine; SoundcheckController only calls atomics and `lastDeviceErrorLock_`; SessionLogger has its own mutex). `NotchController::stop()` already joins only a running thread, so "join only running" was already true; the outbox flush for stopped ones is deliberate. No code change.
